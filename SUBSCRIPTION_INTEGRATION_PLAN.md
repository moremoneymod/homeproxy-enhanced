# План: встроенные VPN-подписки в форке Re:HomeProxy

## Что есть сейчас

- `root/etc/homeproxy/scripts/update_subscriptions.uc` импортирует share-ссылки, base64, sing-box JSON и массив Xray-конфигураций. `parse_xray_config()` выбирает outbound `proxy` либо первый подходящий. Узлы помечаются `grouphash = md5(URL без #)`; фильтр работает по regex в имени. Настройки подписок общие для всех URL.
- `root/etc/homeproxy/scripts/homeproxy.uc:wGET()` вызывает `wget` с одним настраиваемым User-Agent и таймаутом 10 секунд. Пользовательские HTTP-заголовки, в частности `x-hwid`, не поддерживаются. Перед разбором Xray JSON загрузчик пробует фиксированный User-Agent `HiddifyNext/2.0.0`, затем общий пользовательский.
- `htdocs/luci-static/resources/view/homeproxy/node.js` показывает URL и глобальные параметры, запускает импорт. `root/etc/init.d/homeproxy` ставит ежедневный cron; `update_crond.sh` вызывает загрузчик.
- `root/etc/homeproxy/scripts/generate_client.uc` строит URLTest из сохранённых списков ID `main_urltest_nodes`, `main_udp_urltest_nodes` и `routing_node.urltest_nodes`. Удалённые ID отфильтровываются при генерации, но новые узлы подписки в списки автоматически не попадают.
- Обновление импортера сохраняет существующие узлы по ID `md5(label)` и удаляет исчезнувшие. Смена имени меняет ID; одинаковые имена в разных подписках могут столкнуться. При частичном провале одной подписки общий успешный результат может всё же привести к удалению её прежних узлов: `node_cache[groupHash]` сначала пуст, а проверка пустоты в цикле зависит от состояния карты. Это требует отдельного теста и исправления до включения автоматического управления списками.

## Что делает обходное решение `C:\Users\Ivan\Documents\vpn-sub`

- `bridge/bridge.py` на Debian LXC получает исходный HTTPS URL с `x-hwid` и `User-Agent: v2rayNG/1.10.5`, читает массив Xray-конфигураций, выбирает VLESS/REALITY/TCP outbound `proxy`, фильтрует профили по флагу страны, словам и `Auto`, преобразует их в `vless://` и отдаёт `/sub`.
- Сервис обновляет кэш раз в 6 часов, атомарно сохраняет последнюю удачную выдачу и оставляет её при ошибке. `/reload` запускает только обновление кэша LXC. Контроль доступа по CIDR и LAN firewall нужны, поскольку `/sub` содержит учётные данные узлов.
- `openwrt/urltest-sync.sh` после штатного импорта на роутере выбирает узлы по `grouphash`, проверяет минимальное количество, заменяет `routing_node.urltest_nodes`, делает резервную копию и перезапускает HomeProxy при изменении. Отдельный cron запускает синхронизацию каждые 5 минут. Полная цепочка состоит из трёх несвязанных обновлений: провайдер → LXC → импорт Re:HomeProxy → URLTest.
- Фильтрация стран основана на названии/флаге профиля, не на фактическом GeoIP. Мост поддерживает только узкий набор протоколов и транспортов, хотя встроенный импортер уже понимает больше форматов.

## Целевая модель

Подписка становится отдельной UCI-секцией с постоянным ID, названием, URL, User-Agent, разрешённым набором HTTP-заголовков (включая `x-hwid`), интервалом обновления, фильтрами и статусом последней попытки/успеха. Секретные заголовки остаются на роутере. Подписка напрямую загружается и разбирается тем же ucode-парсером, без LXC и перекодирования в share-ссылки.

URLTest может выбирать состав по ID одной или нескольких подписок и типам узлов. Ручной список остаётся доступным. Обновление подписки и пересчёт зависимых URLTest выполняются в одной согласованной операции; при отсутствии пригодных узлов действующая конфигурация сохраняется и показывается ошибка. Не создавать отдельный cron для URLTest.

## Этапы внедрения

1. **Зафиксировать контракт и миграцию.** Определить UCI-схему `subscription` как повторяемые секции, стабильный `subscription_id`, поля для заголовков/фильтра/периода и режим URLTest `manual`/`subscription`. Сохранить чтение текущего `subscription.subscription_url` и сделать однократную миграцию с бэкапом. Не переносить секреты в логи или диагностические отчёты.
2. **Доработать HTTP-загрузку.** Добавить per-subscription User-Agent и заголовки через безопасную передачу аргументов `wget`; ограничить размер ответа, схему URL и время загрузки, учесть redirects и ошибки HTTP. Не подставлять заголовки в строку shell-команды без экранирования. Убрать жёсткую попытку Hiddify UA или сделать явно выбранный профиль совместимости. Скрывать URL с токенами и значения заголовков в логах.
3. **Выделить конвейер разбора.** Использовать существующие парсеры sing-box, Xray и share-ссылок, расширяя их только по реальным примерам провайдера. Для массива Xray сохранить выбор `proxy`, REALITY-поля и название профиля. Добавить фильтры стран/слов/Auto на уровне конкретной подписки; явно указать в UI, что страна определяется меткой. Вынести чистые операции разбора/фильтрации для тестирования без сетевого доступа.
4. **Сделать безопасное обновление узлов.** Сначала полностью загрузить и проверить каждую подписку, затем построить diff и применять его. При ошибке сети, неверном формате или подозрительно малом числе узлов сохранять прежнюю версию именно этой подписки. Различать валидный пустой результат и ошибку; удаление всех узлов требовать отдельной политики. Ввести стабильный ID узла на основе ID подписки и нормализованных параметров подключения, разрешить одинаковые метки и не ломать ссылки на узлы при переименовании. Учитывать удалённые подписки и пользовательские узлы отдельно.
5. **Интегрировать URLTest.** В `generate_client.uc` и формах LuCI добавить динамический источник узлов по ID подписки для основного, UDP и routing URLTest, с выбором допустимых типов. При генерации применять только успешно импортированный набор; не переключать маршруты на случайный первый узел при сбое обновления. Перезапускать сервис только при изменении эффективной конфигурации; предусмотреть безопасный откат, если новая конфигурация не проходит проверку ядра или запуск.
6. **Обновить LuCI и расписание.** На странице подписок дать отдельные карточки: URL, заголовки, фильтры, частота, «Обновить сейчас», число узлов, время успеха и причина последней ошибки без секретов. Показывать предварительный результат фильтра и связь с URLTest. Планировщик обновляет подписки по их интервалам, с блокировкой параллельных запусков и единым ручным действием для всей цепочки.
7. **Проверить и задокументировать.** Добавить фикстуры с обезличенным Xray JSON и тесты: HWID/UA, фильтр стран, дубликаты имён, смена метки, частичный провал, пустой ответ, удаление подписки, динамический URLTest, откат после ошибки запуска. Проверить на OpenWrt с opkg и apk и на обоих поддерживаемых ядрах. Описать миграцию с LXC, бэкап, восстановление и удаление старых cron/systemd задач после успешного перехода.

## Порядок первой реализации

Начать с одной подписки типа Xray JSON и одного routing URLTest, повторив текущий сценарий `vpn-sub`. Затем добавить общую модель нескольких подписок и других форматов без отдельного сервиса. Критерий готовности: исходный URL и HWID задаются в LuCI, обновление напрямую создаёт подходящие узлы и автоматически меняет состав выбранного URLTest; при сбое провайдера рабочий набор и маршрутизация сохраняются.

## Решения, которые стоит принять перед кодом

- Хранить HWID как отдельное поле с маскировкой или разрешить список произвольных заголовков; для безопасности предпочтительнее ограниченный список с явной поддержкой `x-hwid`.
- При сознательно пустом результате фильтра сохранять старые узлы или разрешить пустую группу по отдельному переключателю; безопасное значение по умолчанию — сохранять.
- Привязывать URLTest к одной подписке или к нескольким; схема может поддержать несколько, даже если первый экран UI даст одну.
